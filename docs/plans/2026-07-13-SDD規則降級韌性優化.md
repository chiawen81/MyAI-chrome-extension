# SDD 規則降級韌性優化（切換 Sonnet 時維持品質）

> status: draft（待審閱，尚未定案）
> 建立日期：2026-07-13

## 1. User Story

身為專案唯一開發者，我想要把目前依賴高階模型（Fable/Opus）判斷力的 SDD 規則，改寫成較弱模型（Sonnet）也能機械式遵循的形式，以便切換模型省成本時，開發品質與文件紀律不降級。

**約束**：每項優化必須通過成本效益檢核——(a) 現有機制下 Sonnet 是否**真的**會誤判；(b) 改進效益是否大於多耗的 token（特別注意 CLAUDE.md 是每次對話的固定成本）。

## 2. Spec

### 2.1 風險點盤點（現況 → Sonnet 誤判可能性 → 結論）

| # | 依賴判斷力的環節 | 現況機制 | 誤判可能性 | 結論 |
|---|---|---|---|---|
| R1 | 「這個改動算不算跨執行環境」→ 決定是否先讀 ARCHITECTURE.md 第 1 節 | CLAUDE.md 用概念描述（「跨執行環境通訊、訊息型別、注入邏輯」） | **中高**——概念判斷，Sonnet 容易覺得「我只是改個函式」而跳過 | ✅ 優化（O1） |
| R2 | 實作到尾聲記得停在「文件同步與收尾」前讓人驗收 | CLAUDE.md 任務執行節奏規則，靠模型當下記得 | **中**——長 session 尾段規則遵循度會掉 | ✅ 優化（O2，寫進計畫文件本身） |
| R3 | `/sdd-fix` 判斷「有沒有改變對外行為」以決定是否升級場景四 | sdd-fix.md 有逃生門規則，但「對外行為」定義只在指南（人看的文件），模型看不到 | **中**——定義缺席時 Sonnet 會自由心證 | ✅ 優化（O3，一行定義搬進指令） |
| R4 | `/sdd-plan` 產出 Spec 的完整度（邊界條件、錯誤處理、驗收可勾選） | 範本有列結構，但無自檢步驟 | **中**——Sonnet 常列出結構但內容偏薄 | ✅ 優化（O4，低成本自檢清單） |
| R5 | 場景分派（走哪個 /sdd-* 指令） | **由使用者手動選指令**，模型不參與 | 低 | ❌ 不動 |
| R6 | `/commit-session` 的 hunk 歸屬判斷 | skill 已有「不確定就停下問、不猜」硬規則 | 低 | ❌ 不動 |
| R7 | 任務尾聲的文件同步檢查（非 /sdd-done 收尾的零星改動） | CLAUDE.md 規則靠記憶；/sdd-fix、/sdd-done 各自已內建同步步驟 | 中，但**殘餘暴露面小**（只剩不走指令的臨時任務） | ⏸️ 緩做（O5，hook 留第二階段） |
| R8 | Sonnet 長期累積的文件漂移 | 指南 6-B 脫鉤稽核範本已存在 | — | ❌ 不加新機制，靠既有 6-B 當安全網（切 Sonnet 後可提高頻率） |

### 2.2 定案優化項目

**O1：跨環境必讀規則改為「檔案路徑觸發」**（CLAUDE.md）
- 現行「改動跨執行環境通訊…前務必先讀」條目，補上機械式觸發條件：凡編輯 `src/background/`、`src/content/`、`src/shared/messages.ts` 任一路徑前，必先讀 ARCHITECTURE.md 第 1 節；純改 `src/options/`、`src/popup/` 內部 UI 不需要。
- 效益：把概念判斷變成路徑比對，Sonnet 無從自由心證。
- 成本：CLAUDE.md 約 +2 行（每次對話固定成本約 +40 token）。**效益 > 成本**。

**O2：停點寫進計畫文件，不靠模型記憶**（sdd-plan.md 範本）
- `/sdd-plan` 範本新增要求：Tasks 末項固定為「文件同步與收尾」，且該項前一行明標 `⛔ 停點：先提示使用者手動驗收（chrome://extensions），通過後才執行本項`；需真實環境驗證的中途 task 也要求在計畫中標註停點。
- 效益：實作 session（可能是 Sonnet）讀計畫文件就會看到停點，規則存活於產出物而非模型記憶。CLAUDE.md 既有節奏規則不動、當雙保險。
- 成本：範本 +3 行，只在執行 /sdd-plan 時載入。**效益 > 成本**。

**O3：「對外行為」定義內嵌 /sdd-fix**（sdd-fix.md）
- 把指南 §0 判斷準則搬一行進指令：「對外行為＝使用者可感知的行為（翻譯結果、UI、快捷鍵、儲存格式）；改註解／log／typo 不算。拿不準一律停下改走場景四。」
- 成本：+2 行，僅指令執行時載入。**效益 > 成本**。

**O4：/sdd-plan 產出前自檢清單**（sdd-plan.md）
- 範本尾端加：產出計畫後、交給使用者前，逐項自檢——① 每條驗收標準可勾選且可觀察 ② 邊界條件與錯誤處理至少各一條（真的沒有要寫「無，原因：…」）③ 每個 Task 標註影響檔案路徑 ④ 功能涉及 R1 路徑時，規劃前已讀 ARCHITECTURE.md 第 1 節。
- 成本：範本 +5 行；自檢輸出約多 100~200 token／次計畫。**效益 > 成本**（計畫是低頻高槓桿產物，Spec 偏薄的下游返工遠貴於此）。

### 2.3 評估後明確不做／緩做

- **不做**：場景分派自動化（R5，使用者手動分派已是最強機制）、/commit-session 加強（R6）、整套 SDD skill 化（指南 §7 已評估過）。
- **緩做（O5）**：Stop hook 文件同步提醒。可設計成條件式腳本（git 偵測 src/ 有異動但 CHANGELOG 未動才注入一行提醒），token 近零，但 hook 建置維護成本存在、且殘餘暴露面小（R7）。**維持指南既列的第二階段定位**：切 Sonnet 實跑 2~3 個任務後，若實際觀察到漏同步再建。
- **不做**：把 SDD 指南改寫給模型讀。指南定位是給人看的操作手冊，模型的行為約束已由 CLAUDE.md＋slash commands 承載，重複餵指南只會虛耗 token。
