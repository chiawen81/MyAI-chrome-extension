# 樣式設定：自訂顏色改用色盤選色＋即時預覽

> 對應任務看板：[BOARD.md #11](../BOARD.md)（發現於發想／待辦區）
> 規格書對應章節：REQUIREMENTS.md 無，為新需求

## 1. User Story

身為外掛使用者，我想要在「樣式」設定頁的文字顏色／背景顏色欄位旁，直接用瀏覽器原生色盤點選顏色並即時看到色塊預覽，以便不必手動查色碼或憑空猜測顏色效果；同時我仍想保留原本的文字欄位手動輸入色票（含具名色如 `royalblue`），兩者雙向同步。

## 2. Spec

### 2.1 現況

- `src/options/index.html` 的「樣式」分頁中，`#style-color`（文字顏色）與 `#style-bg`（背景顏色）皆為 `<input type="text">`，可輸入任意合法 CSS 顏色字串（hex 3/6 碼、具名色、`rgb()`/`rgba()` 等），留空代表「不覆寫，沿用原文顏色」。
- `src/options/options.ts` 的 `setupStyleTab()` 在欄位 `input`/`change` 時呼叫 `apply()`：寫回 `settings.style`、重新產生預覽 CSS（`buildTranslationCss`）、呼叫 `persistSettings()` 存入 `chrome.storage`。
- `src/shared/types.ts` 的 `StyleSettings.textColor` / `backgroundColor` 皆為 `string`，允許空字串（代表不覆寫）。**此資料結構本次不變動。**

### 2.2 新增行為

在 `#style-color`、`#style-bg` 兩個文字欄位旁，各新增一個 `<input type="color">` 色盤按鈕，兩者雙向同步：

**A. 色盤 → 文字欄位**
- 使用者點色盤選色後，選定顏色立即以 6 碼小寫 hex 格式（如 `#1a73e8`）回填到對應文字欄位。
- 回填後觸發既有 `apply()` 流程：更新 `settings.style`、重繪即時預覽、`persistSettings()`。

**B. 文字欄位 → 色盤**
- 使用者手動編輯文字欄位時，嘗試將目前輸入值解析為色盤可用的 hex 值：
  - 合法可解析（hex 3/6 碼、具名色、`rgb()`/`rgba()` 等瀏覽器認得的 CSS 顏色）→ 解析出的 RGB 部分正規化為 6 碼 hex，同步更新色盤色塊；**不覆寫文字欄位本身的值**（保留使用者原始輸入，例如具名色 `royalblue` 或帶透明度的 `rgba()`，不會被強制改寫成 hex）。
  - 無法解析（空字串、打字中間狀態如 `#1a`、無效字串）→ 色盤色塊維持前一個有效顏色不變，不報錯、不清空文字欄位、不阻擋輸入。
- 文字欄位既有「留空 = 不覆寫」語意不變：欄位留空時 `buildTranslationCss` 仍不產生對應 CSS 規則；色盤本身因原生限制無法呈現「無顏色」狀態，會停留在最後一個有效顏色（或初始中性色），但這個狀態**不會**回頭覆寫文字欄位或誤觸發覆寫行為。

**C. 初始載入**
- 開啟樣式分頁時，依當前 `settings.style.textColor` / `backgroundColor` 值初始化色盤色塊（套用同一套 2.2-B 的解析規則）。
- 若初始值為空或無法解析，色盤顯示瀏覽器預設中性色（通常為 `#000000`），但不視為「使用者選色」，不觸發 `apply()`、不覆寫文字欄位、不誤存入 `chrome.storage`。

### 2.3 邊界條件與例外處理

| 情境 | 行為 |
|---|---|
| 文字欄位為 3 碼 hex（如 `#fff`） | 展開為 6 碼（`#ffffff`）供色盤使用；文字欄位原值不變 |
| 文字欄位為具名色（如 `royalblue`） | 解析出對應 RGB 正規化為 hex 供色盤顯示；文字欄位仍保留 `royalblue` |
| 文字欄位為 `rgba()` 帶透明度 | 色盤僅能反映 RGB 部分（`<input type="color">` 原生不支援 alpha），透明度資訊不會遺失，因為文字欄位的原始值不被色盤覆寫 |
| 文字欄位打字到一半（無效值） | 色盤維持前一個有效顏色，不跳動、不清空、不報錯 |
| 文字欄位留空 | 維持既有「不覆寫」行為；色盤停留在最後有效色或中性預設色，兩者互不影響 |
| 色盤與文字欄位事件互相觸發 | 只有「色盤變更」會覆寫文字欄位；「文字欄位變更」只更新色盤色塊、不回頭再次覆寫文字欄位，避免不必要的迴圈與游標跳動 |
| YouTube 字幕／網頁譯文渲染邏輯 | 不受影響，`StyleSettings` 資料結構與 `buildTranslationCss` 邏輯不變，僅 options 頁呈現方式改變 |

### 2.4 驗收標準

- [ ] 開啟 options 頁「樣式」分頁，文字顏色與背景顏色輸入框旁各顯示一個色盤按鈕（`<input type="color">`）
- [ ] 開啟頁面時，若設定值為合法顏色（hex 或具名色），色盤色塊顯示對應顏色；若欄位留空，色盤顯示中性預設色但不影響「留空 = 不覆寫」的行為
- [ ] 點擊色盤選色後，選定顏色即時（不需按確定或離開欄位）以 hex 格式回填到旁邊文字欄位
- [ ] 點擊色盤選色後，下方「即時預覽」區塊立即套用新顏色
- [ ] 選色後的值會透過既有 `persistSettings()` 存入 `chrome.storage`，重新整理 options 頁後仍保留
- [ ] 在文字欄位手動輸入合法 CSS 顏色值（hex 或具名色如 `royalblue`）後，色盤色塊同步更新為對應顏色，且文字欄位內容不被色盤覆寫（仍顯示 `royalblue` 而非被改寫成 hex）
- [ ] 文字欄位輸入無法解析的顏色字串（如打字中的 `#1a`）時，色盤維持前一個有效顏色，不報錯、不清空文字欄位
- [ ] 文字欄位清空時維持「不覆寫」行為不變（預覽區該顏色恢復原文顏色）
- [ ] 文字顏色、背景顏色兩組欄位分別獨立運作，互不干擾
- [ ] `npm run typecheck` 通過

## 3. Tasks

> 依專案節奏：Task 1–3（實作類）連續執行到底，做到 Task 4（文件同步與收尾）前停下，提示手動到 `chrome://extensions` 依 2.4 驗收標準驗收，通過後才進行 Task 4。

1. **調整 options 頁面結構與樣式**
   - 影響檔案：`src/options/index.html`、`src/options/options.css`
   - 在 `#style-color`、`#style-bg` 兩個 `.field` 內，各新增一個 `<input type="color">`（含 `aria-label`，因主 `<label>` 對應的是文字欄位），與既有文字輸入框並排顯示（同一行 flex 排列）。

2. **新增「CSS 顏色字串 → hex」解析輔助函式**
   - 影響檔案：`src/options/options.ts`
   - 新增一個私有函式：輸入任意字串，回傳可供 `<input type="color">` 使用的 6 碼小寫 hex，或在無法解析時回傳 `null`（供呼叫端保留色盤原值）。
   - 僅供 options 頁 UI 使用，不需要放進 `src/shared/`。

3. **串接雙向同步邏輯**
   - 影響檔案：`src/options/options.ts`（`setupStyleTab()`）
   - 初始化：以 Task 2 的解析函式設定兩個 color input 的初始色塊（解析失敗則維持瀏覽器預設值，且不觸發 `apply()`）。
   - 色盤 → 文字欄位：`input`/`change` 時把色盤 hex 值寫入對應文字欄位並呼叫既有 `apply()`。
   - 文字欄位 → 色盤：既有文字欄位的 `input`/`change` 監聽中，額外呼叫解析函式；解析成功才更新色盤色塊，失敗則不動色盤。
   - 確認事件互相觸發不會造成無窮迴圈或游標跳動（色盤變更不應反向再解析寫回文字欄位）。

4. **【停點】手動驗收**
   - 提示使用者到 `chrome://extensions` 重新載入擴充功能，開啟 options 頁「樣式」分頁，依 2.4 逐項驗收。
   - 通過後才繼續 Task 5。
